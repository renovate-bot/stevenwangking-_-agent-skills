# 评测框架细则

配合 SKILL.md 第三章使用。原则：评测回答的是"哪个技能对当前需求最合适"，不是给技能排客观名次。

## 1. 基本信息表（每候选一份）

| 项 | 内容 |
|---|---|
| Skill | 名称 |
| Source | 上游 GitHub 仓库（聚合站候选须溯源至此） |
| Author | 作者 |
| Stars | GitHub stars |
| 安装量 | 以 skills.sh 数据为准 |
| License | 许可证 |
| 最近更新 | 最后提交/发布时间 |
| 依赖 | 运行时、工具、API key 等 |
| 支持的 Agent | 是否含本机在用 Agent（对照 SKILL.md 可见性模型的枚举结果） |
| scripts/ | 是否含可执行脚本 |
| 网络访问 | 是否有外部请求 |
| 环境变量 | 需要哪些变量 |
| 已知局限 | 文档或 issue 中承认的短板 |

## 2. 功能匹配度（维度 A，权重最高）

把用户需求**现拆**成能力项并加权（每次按实际需求拆，禁止套用固定模板），逐项对照技能 README 与 SKILL.md 的实际承诺打分；技能没有提及的能力项记 0 分，不猜测给分。

示例——需求"代码 Review 技能"：

| 能力项 | 权重 |
|---|---|
| Bug 检测 | 25% |
| 架构问题 | 20% |
| 安全问题 | 15% |
| 性能 | 10% |
| 代码风格 | 10% |
| 可操作建议 | 10% |
| 输出结构 | 10% |

## 3. 工程质量（维度 B）

- **description 触发质量**：是否写明"什么时候用"（Use when...）而非泛泛的功能描述——这直接决定技能被自动触发的准确率
- **结构**：SKILL.md + scripts/ + references/ + assets/ 的清晰划分 vs 单文件塞几千行 prompt
- **Progressive disclosure**：核心流程在 SKILL.md、细节沉到 references/，按需加载而不是一次全量进上下文
- **可维护性**：命名规范、版本标注、文档完备度

## 4. 实用性（维度 D）

安装复杂度 / 依赖多少（额外运行时、API key）/ 支持的 Agent 是否覆盖本机在用 Agent / 更新机制是否健全 / 维护活跃度（最近提交、issue 响应）/ 输出一致性 / 与用户工作流的匹配度。

## 5. 综合对比表

维度 C（安全）为硬门槛不设分，细则见 security-vetting.md。

| 技能 | 功能匹配 | 工程质量 | 安全 | 活跃度 | 易用性 |
|---|---|---|---|---|---|

功能匹配/工程质量/活跃度/易用性统一用 1–10 分（固定口径保证跨次可比）；**安全列只写 PASS / WARNING / DANGER 判定**，不设数字分。

## 6. Benchmark 协议（可选，默认不跑）

**触发条件**：用户明确要求"实测对比"；或多个候选静态评测接近、用户同意补实测。

**测试任务**：3–5 个固定任务，覆盖典型场景 + 至少 1 个边缘场景；所有候选用完全相同的任务描述与输入。

**试用方式（不污染全局）**：

```bash
# 免安装试用：把技能写进临时目录并生成 prompt
npx skills use <owner/repo> --skill <name>
```

或安装到隔离的临时项目目录测试——先 `mkdir` 并 `cd` 进入该目录再执行不带 `-g` 的 add（否则会装进当前项目目录），测完 `npx skills remove <skill-name> -y` 清理（不带名称会进入交互式选择）。

**执行载体**：`skills use`（不带 `--agent`）只把生成的 prompt 打到 stdout，它不会替你跑任务（带 `--agent` 会交互式启动 agent，非交互环境勿用）——把 prompt 交由用户在新的 Agent 会话中执行（或用户指定的环境），AI 负责设计任务、生成 prompt、评阅回收的输出；不要在当前会话里"自测"充当候选技能的真实执行。

**重复测试**：输出有随机性的任务每个跑 2–3 次，记录每候选每任务的：平均质量 / 最低质量 / 波动幅度 / 失败模式。

**解读要点**：某些场景特别强但方差大（A 型）vs 均分略低但全面稳定（B 型）是两种不同适用面，按用户的真实场景下结论，不给"谁更好"的空泛排名。

**评分表**（每任务 100 分）：

| 指标 | 分值 |
|---|---|
| 需求理解 | 15 |
| 结果质量 | 30 |
| 一致性 | 15 |
| 可控性 | 10 |
| 专业性 | 15 |
| 输出规范 | 10 |
| 易用性 | 5 |

**声明义务**：输出 Benchmark 结论时必须附带一句——分数是"对本机当前需求的内部适用度评分"，不代表技能的客观优劣排名。
